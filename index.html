Linkly

Enterprise-Grade Creator Identity & Analytics Platform

Engineered from the ground up to survive unpredictable viral traffic surges. Moves beyond traditional CRUD boundaries by utilizing an event-driven architecture that decouples heavy analytics writes from the critical read-path, ensuring sub-millisecond latencies.

Event-Driven Analytics via Redis Streams

To prevent database locking during traffic spikes, click events are instantly published to Redis Streams. A background consumer asynchronously processes heavy IP-geolocation lookups and batch-inserts them into PostgreSQL.

High-Availability Cache Fallbacks

Resilient Checkout API

Fault-Tolerant Distributed Checkout Engine

A battle-tested order processing API engineered to systematically solve four major industry failure scenarios: The Double Charge, The Race Condition (overselling), The Gateway Outage, and The Partial Failure.

Idempotency (The Double Charge)

Strictly enforces unique Idempotency-Key headers backed by PostgreSQL UNIQUE constraints. Safely rejects duplicate requests at the disk level to prevent double-charging impatient users during network retries.

Pessimistic Locking (The Race Condition)

Executes SELECT ... FOR UPDATE queries during inventory deduction to serialize concurrent requests, mathematically guaranteeing stock is never oversold during high-concurrency race conditions.

Circuit Breakers (The Gateway Outage)

Wraps external payment gateway calls with Resilience4j. Dynamically trips the circuit OPEN during outages to instantly "fail fast", protecting the Tomcat thread pool from cascading exhaustion.

State Machine & Reconciliation (Partial Failure)

Decouples local database transactions from external network calls. A background cron job sweeps for stuck PAYMENT_PENDING orders and self-heals the database state based on gateway truth.

MiniGit (mgit)

Educational Version Control System Built From Scratch

A miniature, fully functional version control system built entirely in Go. Designed to demonstrate the core architectural concepts behind tools like Git, featuring content-addressable storage, tree-based histories, and a 3-way merge algorithm.

Content-Addressable Storage

Replicates Git's internal object model by hashing file contents (SHA-1) into immutable blobs. Builds a verifiable directed acyclic graph (DAG) of cryptographic hashes for complete history tracking.

Intelligent 3-Way Merge

Running a merge command automatically locates the lowest common ancestor between branches and attempts a clean 3-way merge of disjoint changes, closely mirroring real Git internals.

Conflict Resolution & Resets

Halts merges upon detecting conflicts, generates standard conflict markers (<<<<<<< HEAD), and implements a full reset subsystem (--soft, --mixed, --hard) to rewrite history.

Reactive Embedded Web GUI

Features a zero-dependency React frontend compiled and embedded directly into the Go binary via //go:embed. The UI reactively polls the filesystem to reflect CLI actions in real-time.
